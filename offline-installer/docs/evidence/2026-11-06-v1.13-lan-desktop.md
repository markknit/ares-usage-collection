# November 6 v1.13 LAN desktop and Tailscale coexistence

The owner requested password-protected VNC on a school's local network without
Internet, for technicians working with a headless ARES server. The November 4
r2 artifact remains unchanged. This source adds LAN access alongside its existing
private Tailscale Serve path.

## Behavior

- LAN SSH and TigerVNC start before optional Internet enrollment. Declining or
  failing enrollment retains the working LAN desktop and command-line access.
- `sudo ares-enable-remote-access --lan-only` keeps the hostname and makes no
  Tailscale calls or service changes. It retains VNC credentials, enables VNC at
  boot and provides `<SERVER-LAN-IP>::5901` for on-site use.
- `$localhost = "no"` and `$SecurityTypes = "VncAuth,TLSVnc"` allow direct network
  access while requiring the existing VNC password. IPv4 wildcard listening also
  retains 127.0.0.1:5901 for Tailscale Serve, including before an adapter has a LAN
  address. No firewall rules are flushed, Docker pruned or content reinstalled.
- The support-only update uses exactly the canonical activation/disable/common/
  configuration helpers and checks its own complete manifest. It backs up the
  previous controls and executes LAN-only activation. The VNC virtual desktop
  restarts; use LAN SSH, AnyDesk or a local terminal to apply it.
- Updated technician instructions distinguish local-IP access without Tailscale
  from off-site access using the Tailscale app. The two-page overview and four-page
  technician PDF were rendered and visually reviewed. The new four-page editable
  Word guide retains all 69 source content blocks and was also fully reviewed.
